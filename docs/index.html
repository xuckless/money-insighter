Your money, on your machine.

Money Insighter is a desktop app for Canadian banking, built on Plaid. Connect your banks and every account and transaction syncs into a Postgres database that lives in your own user folder. There is no server of ours, because there is no server of ours to have.

  • Linux & Windows
  • Electron + two Go services
  • Embedded Postgres
  • Plaid Hosted Link
  • No telemetry

Plain claims, and how each one is kept

See an overspend on the 11th, not the 30th

Spending is drawn against an even pace of your budget, so a category running hot shows up while you can still do something about it.

Only categories of kind spending are paced: bills land on a schedule in large amounts and would make the line jump. lib/insights/spending.ts

Know what is safe to spend

Your cash balance is projected forward from the paycheques, bills and card payments it already knows about, with the low point marked and a cushion you choose.

Cash means chequing plus savings; card spending reaches cash only through the card payment, which is its own stream. lib/insights/cashflow.ts

Catch a subscription price rise

Recurring charges are found in your own history — no paid add-on needed — and a price change is flagged before the next bill.

A merchant's charges on one account, in one direction, become a stream when they land at a steady interval for a steady amount and the last one is recent. lib/insights/detect.ts

Fix a category once

Re-categorise a transaction and you can set a rule for every transaction from that merchant, past and future, in one move.

The rule is a row in merchant_rules; the topper's views apply it in SQL over merchant_key, so every chart moves together. postgres-topper/internal/views/

Categories that are yours

Twenty-one to begin with. Rename them, recolour them, add your own, and choose where a removed category's transactions go.

They live in topper.categories, seeded from the built-in set the app mirrors. Four kinds decide the behaviour: spending is paced and budgeted, bills are budgeted only, income and transfers are neither. desktop/src/shared/categories.ts

Worth a look

A short list of things the app noticed: a price rise, a category ahead of pace, transactions with no category yet.

Notes are weighted runs of plain text, not rendered strings, so the rules stay unit-testable and the page decides how a strong run looks. lib/insights/notes.ts

    Privacy

    Not a promise — an architecture

    "Your data stays on your machine" is easy to write on a landing page. Here is what actually enforces it.

    What you are toldWhat makes it true
    Nothing leaves your computer but calls to Plaid. Thirteen Plaid endpoints are called, all from internal/plaid/http.go. There is no other outbound code path, no telemetry, no analytics, and no update server — publish is null in the packaging config.
    Your bank tokens are encrypted. AES-256-GCM, stored as nonce ‖ ciphertext ‖ tag, with the Plaid item id as additional authenticated data — so a blob copied onto another item's row will not decrypt. Keys are versioned, so they can be rotated.
    The app cannot move money. Plaid is asked for the transactions product only. There is no payment initiation, no transfer scope, nothing to authorise a movement of funds.
    Even the app cannot read its own tokens back. The REST layer never exposes encrypted_access_token or its key version — they are on a column denylist, so no query can return them.
    The window is not trusted. The renderer runs sandboxed, with context isolation and no Node, under a content security policy that loads nothing from the network. It can reach the services only through four checked IPC channels and never holds a token, a port or a database URL.
    Your secrets are in the OS keyring. Everything sensitive is encrypted with Electron's safeStorage: libsecret or KWallet on Linux, DPAPI on Windows, Keychain on macOS. The database itself authenticates with scram-sha-256, even over loopback.
    There is no account to breach. There is no sign-up, no password and no user record anywhere. The only credential in the system is your own Plaid key pair.

    About the demo data. The person in these screenshots does not exist. The last 30 days of their banking went through Plaid Sandbox for real — a real link, a real token exchange, a real /transactions/sync, and Plaid's own categorisation of every merchant. Plaid's Sandbox serves only 30 days, so the earlier months were written straight into the database in the same shape, carrying the categories Plaid itself gave those merchants. Daily balance history is wound back from the transaction ledger, because the app only starts recording balances the day an account is linked.

    All of it is generated by a committed script, and the capture refuses to take a screenshot if a real key, secret or path is still on screen.
